● 对，目录这点你说对了，但"两个方向""大部分功能"这两个说法我得帮你校正一下——会更准确：

  ① 是不是两个方向？—— 不是，是"同一个东西的两种外壳"

  功能上它俩完全是同一个 App，不是两条分叉。区别只在外壳形态和跑在哪：

  ┌──────────┬────────────┬──────────────┬────────────┐
  │          │    本质    │     外壳     │   跑在哪   │
  ├──────────┼────────────┼──────────────┼────────────┤
  │ 网页端   │ 你的 App   │ 浏览器标签页 │ 服务器     │
  ├──────────┼────────────┼──────────────┼────────────┤
  │ 桌面宠物 │ 同一个 App │ 透明置顶小窗 │ 你本地电脑 │
  └──────────┴────────────┴──────────────┴────────────┘

  打个比方：就像同一个网站，你可以用 Chrome 打开，也可以"装成一个 App 放桌面上"。内核是同一份，只是显示的容器不一样。

  ② 桌面宠物是不是集成了网页的功能？—— 不是"集成大部分"，是"100% 就是网页本身"

  这是最关键的一点：桌面宠物没有重写、也没有挑着搬任何功能。它做的事是——直接把你的网页加载进一个透明小窗里显示（加载 http://你的服务器/?pet=1）。

  所以网页有啥它就有啥，是全部，不是大部分：
  - ✅  Live2D 角色、表情、口型
  - ✅  视觉看图、流式语音、好感度、记忆画像、主动搭话…
  - ✅  你以后给网页加的任何新功能，宠物自动就有了（因为它加载的就是同一个网页）

  唯一一个实际打折扣的：语音输入（麦克风听写），在 Electron + HTTP 下可能不稳。其它全部正常。

  ③ 代码到底在哪

  - desktop/ 目录：只是那个"外壳/相框"（Electron 窗口、托盘、拖拽、打包），约 5 个文件，不含任何业务逻辑。
  - 真正的功能代码一行没动，还在 frontend/index.html + backend/。
  - 我只往 index.html 里加了一小段"宠物模式"开关（?pet=1 时把网页变成只剩角色的样子）——这段是跟网页走 deploy.ps1 上服务器的。

  ---
  一句话总结：桌面宠物 = 你的网页 + 一个透明置顶的相框。相框在你本地电脑跑，画框里装的还是服务器上那个网页。
